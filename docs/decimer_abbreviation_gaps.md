# Finding and adding DECIMER abbreviation gaps

DECIMER doesn't train on real scanned literature — it trains on synthetic
structure depictions generated by [RanDepict](https://github.com/OBrink/RanDepict),
which renders common shorthand "superatom" labels (Boc, Bn, Ph, ...) using
a fixed abbreviation-to-SMILES table. If a real, standard abbreviation
never appears in that table, DECIMER has essentially never seen it during
training and will misread it as something else — often a real, rare
element symbol that happens to look similar, with no confidence penalty,
since from the model's perspective it isn't uncertain: it's confidently
reading the wrong thing.

**Confirmed case:** "Ts" (tosyl) is absent from every abbreviation source
in the training pipeline. DECIMER reliably substitutes the element
thallium (`[Tl]`) instead — reproducible on the public DECIMER web app,
not just this pipeline. Since thallium organometallics are implausible in
routine synthetic-chemistry SI documents, and the misread happens at
moderate-to-high confidence (not a low-confidence guess), the
`MEAN_CONFIDENCE_THRESHOLD` gate in `ingest/stage3_figure_extraction/decimer_extract.py` cannot
catch this on its own. Instead, `decimer_extract.py` OCRs the source image
for any label in `KNOWN_MISSING_ABBREVIATIONS` and forces
`need_human_review=True` whenever one is found, regardless of DECIMER's
own confidence score.

This doc is how to check whether some *other* abbreviation belongs on
that list too, and how to add it correctly.

## Step 1: confirm the abbreviation is actually missing

Don't guess — check DECIMER's actual training vocabulary directly. There
are two sources, both plain text/data files you can grep:

**RanDepict's own abbreviation tables** (its supplementary superatom
lists, independent of RDKit's defaults):

```bash
git clone --depth 1 https://github.com/OBrink/RanDepict.git /tmp/RanDepict
grep -inE '(^|[[:space:],])YOUR_ABBREVIATION([[:space:]]|,|$)' \
  /tmp/RanDepict/RanDepict/assets/*.txt \
  /tmp/RanDepict/RanDepict/assets/*.smi
```

**RDKit's own built-in default abbreviation list** (a separate source
RanDepict also draws on):

```bash
gh api repos/rdkit/rdkit/contents/Code/GraphMol/Abbreviations/AbbreviationsUtils.cpp \
  -H "Accept: application/vnd.github.raw" > /tmp/rdkit_abbrevs.cpp
grep -inE '(^|[[:space:]])YOUR_ABBREVIATION([[:space:]]|$)' /tmp/rdkit_abbrevs.cpp
```

If either search finds a real entry, DECIMER most likely *has* seen that
abbreviation during training — don't add it to the list. Only add
abbreviations confirmed absent from **both** sources. (Reference: at last
check, common ones like Ms, Tf, Bs, Cbz, Fmoc, Boc, Bn, Ph, Ac, Bz, Tos,
TBDMS, TIPS, and Troc were all present. "Ts" specifically was missing even
though the less-common "Tos" spelling was present. Ns, Piv, and Trt were
also missing but lower-impact — worth checking if they show up often in
your corpus.)

## Step 2: confirm OCR can actually read it

Tesseract's *default* page-segmentation mode fails completely on a tight
single-structure crop with sparse embedded text — even when the label is
perfectly legible to a human. You must use `--psm 6` (assume the crop is
one uniform block of text):

```python
from PIL import Image
import pytesseract

img = Image.open("path/to/a/real/structure/crop/containing/the/label.png")
data = pytesseract.image_to_data(img, config="--psm 6", output_type=pytesseract.Output.DICT)
for w, c in zip(data["text"], data["conf"]):
    if w.strip():
        print(repr(w), c)
```

Confirm the target label shows up as its own token with confidence
comfortably above `OCR_MIN_CONFIDENCE` (currently 50) on at least a couple
of real examples pulled from your actual corpus, not a synthetic test
image — real scan/render quality varies.

## Step 3: check for false positives

Run the same OCR check against a handful of real structures that do
*not* contain the label, especially ones with other short embedded text
(atom labels like `CH3`, `NO2`, `Br`, or unrelated short abbreviations).
Tesseract produces plenty of low-confidence noise on line art; the goal
is to confirm your label's exact lowercase text doesn't turn up as a
same-confidence false match on unrelated content. If you see any
same-abbreviation false hits, either the label is too short/ambiguous to
check this way, or `OCR_MIN_CONFIDENCE` needs to be raised for it
specifically (this may require adding a per-abbreviation confidence
override rather than a single shared constant, if a genuinely ambiguous
case comes up).

## Step 4: add it

In `ingest/stage3_figure_extraction/decimer_extract.py`, add the lowercase label to
`KNOWN_MISSING_ABBREVIATIONS`:

```python
KNOWN_MISSING_ABBREVIATIONS = {"ts", "your_new_abbreviation"}
```

That's the only code change needed — `_detected_missing_abbreviations()`
and the `need_human_review` logic already generalize to the whole set.

## What this deliberately does not do

This flags for human review; it does not attempt to auto-correct the
SMILES (e.g. swapping a detected `[Tl]` for the real tosyl fragment).
Auto-substitution would require assuming the misread is always a single
deterministic token swap in a known position, which hasn't been verified
across enough real examples to trust silently. Flagging is the safe
default — it costs a human a look, but never risks silently emitting a
wrong structure into downstream data.
